# v1 → v2：优先迁移清单

这是替换旧版冲突的变更，不是追加可选段落。

| v1要求 | v2当前要求 |
|---|---|
| USB+卧室RTSP+客厅RTSP同时工作 | 一个CameraManager，一次只开一路本地相机/录像 |
| 摄像头按房间绑定 | 场景×设备×机位；四场景可共用一个设备 |
| 默认source=0、自动后端回退 | 首次人工选择；path/backend重解析，不静默开别的设备 |
| 多路模型/跟踪器调度 | 一套权重，一个当前上下文；切换重置跟踪/规则 |
| 康复启用不得停其他房间监测 | 本期本来就没有其他活动流；未启用场景明确未监测 |
| 雷达首周必须接通 | C1001、ESP32、pySerial仅未来扩展，不影响当前启动/验收 |
| 第3天多路、第5天雷达 | 第2天切换生命周期，第5天输入兼容/可选外接实测 |
| 多房间首页状态 | 场景/输入/机位选择为核心；无虚构房间正常状态 |
| 每个设备一套区域 | 每场景-设备-机位-版本各自区域；换机位必须确认 |
| 隐私暂停后可能恢复旧状态 | 释放相机；恢复预览；重建时间线，不补计 |

## 迁移顺序
1. 备份项目与数据库；记录已稳定运行的代码，不推倒重写。
2. 更新AGENTS.md和主规范，移除README、启动脚本、配置中的旧硬件前置要求。
3. 将所有VideoCapture集中到输入层。一次只允许一个owner；业务只接FramePacket/PoseFrame。
4. 建devices与scene_profiles；旧数字index转“待重新选择”，不可猜对应设备。未知机位设未确认。
5. 先做预览/开始/停止、设备选择和切换，再接旧康复引擎。
6. 添加generation/run上下文；清理旧队列、tracker、滤波、计时和反馈。
7. 改测试：保留康复/事件有效性，新增设备匹配、切换、未知/未启用、镜像ROI。雷达测试移未来。
8. 报告添加source_kind、usage_context、scene/profile/设备版本。旧记录保留，缺少可比元数据时不硬做趋势。

## 第一版仍必须保留
报警不因断流/换模式消失；缺测不算正常；真实/回放分离；动作目标人工配置；历史保存；视角和质量拒测；来源和许可证。

## 不要顺便做的事情
不额外采购摄像头、雷达或计算盒；不训练新模型；不为“未来可扩展”先引入消息中间件、多路并行、自动全屋身份匹配。

本次未把用户粘贴的某型号价格/采购候选变成软件强制依赖。硬件协议优先于型号；内置相机先验证，普通UVC外接设备后续再测。
