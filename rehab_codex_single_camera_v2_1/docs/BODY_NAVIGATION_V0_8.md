# 人体导航与摄像头测试 · 0.8

2026-09-09：按用户要求，将原生 PySide6 首页调整为“测试摄像头”和“选择身体部位”两个入口；不新增远程服务、关节算法或动作模型。

## 使用路径

1. 启动仍只枚举、恢复设备选择，不自动开启摄像头。
2. 顶部“打开摄像头并测试”无需选择动作或填写个人档案。点击后独立窗口显示实时画面、实际分辨率与接收帧率；没收到有效新帧时不能显示已收到画面。
3. 点击“关闭摄像头”，释放成功后返回原页面并保留设备、部位选择。Esc 和窗口关闭也走相同释放流程；失败时留在窗口允许重试，不开第二路输入。
4. 点击人体上的关节图标或名称，右侧只列所选部位。头颈、肩、肘、腕、手指、躯干、髋、膝、踝九组覆盖原有 53 项任务；首页不再默认铺开全部任务。
5. 搜索在选中部位内过滤，未选部位时可跨部位搜索。“全部动作”仍可主动查看所有任务。切换部位清空旧搜索；清单和评估结果入口保留。
6. 选择具体动作后沿用原来的文字/图片位、左右侧、机位准备、确认和开始步骤。测试相机不等于完成机位确认；评估到训练的引用与计划确认门禁不变。

## 采集与数据边界

- 新命令 `camera_test` / `stop_camera_test` 由现有 Runtime 拥有，仍通过 CameraManager 及其 SourceWorker 单路采集。保存 path/backend，每次打开重新枚举解析，不固定 index、不回退到 0。
- 原始画面绕过 VisionWorker.submit 和 SceneController.consume，不加载动作识别模型，不产生骨架、评估计数、舒适基线、患者机位档案、评估/训练会话或视频文件。只保留原设备绑定元数据。
- 测试期间运行层拒绝开始、确认、基线、训练控制、患者资料及清单修改；界面同时禁用相关操作。正在记录或有未保存结果时不能开始测试。
- 打开其他输入前仍先停止、保存、释放。测试结束清空临时画面与确认，不能复用测试画面开始任务；不清空历史报告或未关闭事件。
- 测试帧须匹配当前完整上下文，序号及单调时间递增、接收时间新鲜。迟到/重复/过期帧不刷新看门狗，也不送入分析。模型队列中的旧结果不接入测试。
- 启动超时、断流和采集错误仍使用既有释放流程，空白错误状态不残留成功画面。失败关闭不会解除测试锁；迟到的重复关闭不停止或覆盖后续任务。
- “已收到画面”只说明收到输入；用户仍需人工确认画面内容。它不证明单人识别、RGB 质量、姿态模型就绪或医学测量有效。

## 素材与布局

沿用现有紫色样式，新增一张内置 ImageGen 生成的人体导航图，最终提示词与散列见 `assets/navigation/README.md`。这是部位菜单，不是临床解剖图；标记不表示患者左右侧。具体动作侧别仍在准备页人工选择。本轮没有生成或下载动作示范图。

部位名称和圆形标记都是原生按钮，支持键盘激活和可访问名称，选中状态同步。腕部和手指标记分置图中两只手，避免小窗口点击区域重叠。最低 1100×730，另检查 1360×900 和 1600×1000；宽列表最多两列，卡片限制高度。缺导航图时文字菜单仍可使用。

验证以本轮自动化与实际 Qt 截图为准，见 `VALIDATION_WINDOWS.md`。本轮没有打开真实摄像头、采集真人画面或改变正式用户数据库，不把注入输入的工程测试称为硬件验收。
