# 双摄接入与验收计划

2026-09-10，用户要求接入已到货的摄像头。首次枚举仅见 HD Webcam；用户已说明新设备稍后插入，软件实现继续，实机结果以接入后的检查为准。开发前已保留 Git bundle 与本地数据备份，起点为 `ba9d19f`。

## 本次行为

- 原单摄 / 单录像流程保留；康复任务可选择正面与侧面两个不同设备，两路使用同一显式后端，不按行号或名称猜设备。双摄原始画面测试不推理、不生成评估、不保存录像。
- 所选动作使用其定义要求的正面或侧面相机计数。辅助相机独立显示二维姿态指标；不把一个画面的肩坐标填入另一画面的眼耳公式，也不自动比较两路 track_id 识别人。
- 软件按单调接收时间近邻配对，每张图最多用一次，差值上限 0.12 秒。保留两路序号、时间基准与差值；这不是曝光时间或硬件同步精度。未配上的图不补齐，断流 / 超时停止整个双摄任务。
- 预览后人工确认两幅图都是同一人、正侧面角色和测试侧正确；两路独立跟踪，任一路出现多人或身份变化均中断。姿态缺失时暂停有效计数，缺测不补计。
- 一个 CameraManager 统一拥有两路 SourceWorker；先解析两个设备，再启动。任一路打开 / 上下文变更失败均回滚，停止时尝试释放全部设备；未确认释放则锁定新输入。隐私暂停释放两路。
- 报告保留主结果、逐路测量定义 / 实际采集参数 / 质量、辅助指标和接收时间差；普通导出匿名化设备路径。只有明确授权保存骨架时才保存两路骨架，始终不自动保存原始画面。
- 纵向比较区分单摄与双摄、主机位、两路来源、测量及配对条件；不改写旧记录。

| 测量与存储 | 独立推理 / 跟踪、主指标不跨视角拼接、质量与身份门禁、保存失败恢复、导出授权 | 实现及合成回归通过；两个本地 YOLO 空白帧实跑通过 |

| 自动与实机验收 | 合成回归、临时数据库重开、原生截图；真实两路打开 / 帧参数 / 停止重开单独记录 | 自动结果见下方版本记录；第二设备尚未接入，实机待验收 |

完成范围、实际回归和可直接执行的双路采集检查命令见[0.13.0 双摄记录](../history/DUAL_CAMERA_V0_13.md)。

OpenCV 的属性设置和实际返回值依赖设备、驱动及后端，因此报告分别记录请求值与实测值；接口依据见 [VideoCapture](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html)。0.12 秒是本项目的接收时间筛选参数，不是该接口保证的同步能力。真人计数 / 角度准确度、空间标定和长时间现场可靠性须由对应实测另行验证。
