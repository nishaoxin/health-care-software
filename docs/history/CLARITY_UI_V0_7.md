# 简洁界面与共享摄像头 · 0.7

范围：按 2026-09-09 用户反馈优化现有原生桌面应用，不新增页面框架、模型或提示图片，不改测量定义。

## 页面调整

1. **评估入口**：去掉宣传横幅，53 项动作仍可按部位和关键词查找。卡片只保留名称、拍摄面、观察标记和选择按钮；详细动作文字放在选中之后。
2. **动作提示**：“怎么做”显示当前一条动作文字和三步图片位，不重复整套说明。缺图仍有文字，不使用未审核的新图片。
3. **准备设置**：必要侧别、机位、起点、方向和人工确认保留。可选起点折叠，完整步骤在更多设置中，测量边界可展开。
4. **预览与执行**：主按钮按预览→确认→开始→保存切换。当前反馈固定在画面区下方，不随监视区滚出视野。停止采集仍可见，不能因为精简而取消保存失败处理。
5. **训练中心**：只显示选中的评估/准备计划与入口，去掉横幅和三块重复流程解释；无评估不生成计划，不自动确认或增加训练量。

## 共享设备契约

- 顶部输入栏放在全局外壳内，不随页面重新创建。动作、侧别、子模式、场景、用户、录像往返均不清空设备选择；仍遵循原切换停止/保存/释放协议。
- 手动选择通过运行线程记住设备；机位确认成功也记住所用实时设备，使首次默认设备在实际确认后成为明确偏好。
- 偏好存于既有 SQLite `devices` 表的保留键 `preference:camera:v1`，只含 name/path/backend/vid/pid，不存索引，不改 schema_version=3，不修改旧会话或机位记录。
- 启动先恢复保存接口，再枚举。只能以同接口、同非空 path 且唯一匹配选中本次条目；重新打开仍由 CameraManager 枚举解析当前 index。
- 无偏好时，以名称排除明确虚拟/红外/深度输入；若其余恰有一项且身份可唯一解析，则选中。名称仅用于首次选择提示，不能据此证明 RGB 能力、权限或画面正常。
- 多候选不猜。保存的设备缺失、不唯一、偏好损坏时不回退到别的相机；明确换接口后清空旧选择、要求重新绑定。迟到的另一接口枚举结果被忽略。
- 刷新仅枚举、不打开。预览期间发现选择缺失会撤销开始确认，不私自打开替代输入。设备重新出现可恢复选中，但不自动确认/开始。
- 偏好写入失败显示提示；本次选择仍可使用，不中断当前业务、不伪装成主报告保存失败。
- 全局来源/情境改变时清空不匹配的身体档案展示，防止继续展示或引用旧来源评估。
- 默认选中不代表打开相机。每次切模式仍需要预览、本人/侧别/机位确认；不保留旧测量基线或旧半次动作。
