# 顺畅完成与引导计时 · 0.17.0

2026-09-12。基线 `061c0a6`（0.16.0）。本轮按用户要求把重点放在「能顺利做完一次锻炼」：减少重复确认与重复校准，让普通提示不再打断，并为自动测量撑不住的情况提供明确的引导计时、手动记次和诚实的记录。未新增模型、依赖、动作或示范图片，未放宽任何测量阈值。

## 1. 本轮排查出的问题与对应改动

| 排查到的问题 | 原因 | 本轮改动 |
| --- | --- | --- |
| 摆好位置后还要多点一次“画面已摆好” | `framing` 只是界面确认，没有任何判断 | 画面连续可测量 1.2 秒自动完成这一步；看不清时按钮仍在，可人工点 |
| 重开预览就要重录起点和坐站基线 | `open()` 清空基线，复用比较里含 `preview_epoch` 和 `track_id` | 新增可复用条件集（来源 / 画面尺寸 / 模型 / 动作 / 侧别 / 机位 / 用户），条件一致就沿用并明说“已沿用”，不一致说明具体原因 |
| 跟踪编号跳一下就要重新“已核对，确认准备” | 确认绑定里含 `track_id` | 改为按可复核条件比较；人一直在画面里时只记录“重新识别”，画面里一度没人（≥2 秒）或出现第二个人才撤销确认，并写明原因 |
| 采样时闪一帧没检测到人就整轮取消 | 单帧状态直接取消 | 多人需持续 0.8 秒、完全没看到人需持续 1.5 秒才取消；采样窗口 4→6 秒；跟踪重获时继续本轮，稳定窗口仍要求同一跟踪的连续帧 |
| 起点采样失败后没有下一步 | 只能反复重试 | 失败提示改为“可以再试一次，也可以改用引导计时练习”，并在步骤卡给出明确入口 |
| 一直看不清时反复弹同一条调整要求 | 每次缺测都按 1.5 秒升级 | 同一上下文第二次及以后的缺测需持续 3 秒才再出一条指导；累计缺测 10 秒后给一条安静的可选建议，不弹窗 |
| 镜像预览会关掉摄像头重来 | `_mirror_changed` 调用了整段失效 | 镜像只改显示：撤销本次确认、保留预览与已有准备 |
| 日常活动 / 卧室 / 安全演示没有步骤，只能在“设置”里找区域和许可 | 步骤面板只给康复用 | 三个场景各有 6–7 步的同款步骤卡，缺区域时写明缺哪几个；活动许可由带标签的主按钮完成 |
| 保存后被带到身体档案页，本次结果反而要回头找 | 保存流程里直接切页 | 保存后留在本次任务：步骤卡显示完成小结和“再做一次 / 换一个动作 / 查看详细数据”，身体档案在后台刷新并提示 |
| 训练 / 评估开始太突然 | 点击即开始 | 可关闭的 3 秒倒计时，倒计时期间随时“先不开始”；倒计时只是界面等待，不产生任何数据 |
| 大字界面里没有结束以外的可用操作 | 只有停止采集 / 结束并保存 | 引导计时时增加“暂停提示”和“记一次”，两处界面同步 |

## 2. 引导计时与手动记次

`app/guided.py` 新增固定节奏提示（准备 3 秒 / 动作 4 秒 / 回位 4 秒，版本 `guided-prompt-1`）和 `GuidedEngine`。选择“引导计时练习”后：

- 开始只要求本次预览、明确人工核对和可用画面，不再要求当前帧必须测得所选动作的角度，也不要求先记录起点。多人、画面中断、尺寸变化、保存失败等门禁完全不变。
- `GuidedEngine` 不推断动作阶段、次数、目标或时间指标。它只累计有效可见时间，并按连续有效帧统计一个明确标注的**近似角度范围**（`approximate_range`，注明未按出程 / 回程分期）。
- “记一次（我完成了）”写入 `continuation.self_reports`，记为 `participant_report` / `annotation_origin=human`，与自动次数分开保存，导出时进入 `annotations.csv` 的人工标注行，不进入 `repetitions.csv`。
- “暂停提示”冻结提示时钟；暂停期间不累计有效观察时间，也不累计角度样本，并记录暂停次数与时长。恢复需要再点一次按钮。
- 会话保存 `measurement_mode='guided_timed'`、提示契约、已提示轮数（只表示界面提示过几轮，不表示做了几次）。

引导计时记录**不进入身体档案的评估状态**：它没有动作分期证据，不能作为训练所需的评估依据，也不会把之前成功的评估改写成“不可用”。报告与完成小结都明说这一点。纵向比较版本升到 `recorded-conditions-4`，新增 `measurement_mode`；缺少该字段的旧记录按 `auto_observed` 解释（它们当时都必须通过自动测量门禁），不重算旧报告。

## 3. 提示策略的调整

`GuidancePolicy` 保留 0.14 的分工：数据有效性仍由 `SceneController` 和原引擎决定，提示只负责显示。本轮在其上增加：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `adjustment_after_s` | 1.5 | 首次缺测持续多久才给一条调整指导（未变） |
| `repeat_adjustment_after_s` | 3.0 | 同一上下文后续缺测的门槛，避免反复提示 |
| `candidate_switch_s` | 0.6 | 更换缺失部位前的稳定时间（未变） |
| `offer_after_s` | 10.0 | 累计缺测多久后给出一条可选的引导计时建议 |

提示结果新增 `measurement_quality`（`observed` / `approximate` / `unavailable`）、`offer` 与 `offer_text`，引导计时另有 `prompt_label`、`prompt_remaining_s`、`prompt_cycle`。这些都是界面参数，不是医学阈值，也不改变计次、角度或有效观察的判定。普通界面、步骤卡和大字指导继续共用同一个来源；一次只显示一条指导。

## 4. 准备复用的判定

可复用条件集为：`source_ref`、`source_kind`、`usage_context`、`frame_size`、`schema_id`、`model_manifest_id`、`exercise_id`、`side`、`view`、`participant_id`（双摄另比较辅助路的 `frame_size` 与 `source_ref`）。任一项缺失或不同都不复用。

`preview_epoch` 和 `track_id` 仍然完整保存在 provenance 里，但不再参与复用判定：按现有约定 `track_id` 不是个人身份，重开预览也不代表换了人或换了姿势。这一条放宽由“已核对，确认准备”这一明确人工动作兜底；同时新增了基于证据的撤销（画面中出现第二人立即撤销，画面中一度没有人持续 2 秒撤销），比原来只看跟踪编号更贴近真实变化。

## 5. 不变的边界

- 不编造角度、次数、有效观察时间或保存成功。缺测仍是空值并保留原因，不写成 0。
- 多人、身份不明、输入中断、推理异常、保存失败仍然中止或阻止任务，并保留原有恢复入口（重试保存、备份、明确理由丢弃）。
- 停止采集、隐私暂停与释放两路摄像头的行为不变。
- 引导计时不是测量模式，也不是运动处方；提示节奏是固定的本机计时，不按个人情况调整。
- 未新增模型、依赖、网络功能、动作项目或示范素材；53 项任务与既有测量定义不变。
