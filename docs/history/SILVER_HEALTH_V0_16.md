## 怎样使用

### 1. 从一个入口开始

重启应用后，在侧栏选择“银发健康守护”。先在原页面选好当前用户和来源；数据按参与者、LIVE_CAMERA / REPLAY_FILE / SYNTHETIC、SELF_USE / CONTROLLED_DEMO / TEST 隔离。

顶部“开始训练”返回已有训练中心；“今天的任务”显示已观察记录；“我需要帮助”即使相机没有打开也能记录本地请求；“暂停摄像头”调用原来的真实停止流程，不只是隐藏画面。

没有联网时求助只是本地记录，不会拨号、发送短信或通知异地家人。界面明确显示本机回执不表示电话已接通。

### 2. 双摄分工与活动任务

保留康复正面＋侧面两路同人观察。在银发页面可选 A 主相机或 B 已选第二相机，进入活动、床边或安全场景；只准备所选设备，必须另外打开预览、圈 ROI、确认和开始。返回康复恢复原 A/B 选择，连续切换 B 的场景也不覆盖 A。

当前同一时刻仍只有一个活动场景，不会一边双摄康复一边监护另一个房间。摄像头均由原 CameraManager 管理，新功能不单独打开 VideoCapture 或运行新 YOLO。

活动准备中选择“允许站立和步行 / 仅站立 / 仅步行 / 暂不安排活动任务”，按已核对的个人安排填时长，再确认许可。演示配置沿用原软件的 **坐位 15 秒、站立 5 秒、步行 8 秒**，永久携带 `DEMO_THRESHOLDS`；不是计划举例的 20 / 10 / 15 秒，也不是通用运动处方。

只在同一轨迹、相邻有效观测之间累计时间，空档超过 0.5 秒、归属变化或持续缺测中断任务；不补计出画时间。步行须有直立、合理水平移动和腿部交替证据，单纯框移动仅记可见移动。延期演示为 15 秒、普通为 300 秒；拒绝后本轮不再因起身重新催促。自报与视觉核实分别保存，不能用“仅自报完成”核销一个尚未接受的提醒。

### 3. 功能变化卡

1. 在“功能变化”选取同一人的已保存坐站或肩外展报告。桌面多选可用 Ctrl / Shift。
2. 人工逐条核对并记录真实任务协议、椅子 / 环境、扶物安排；只能给条件确实相同的记录批量填同值。
3. 选 3～5 次合格记录和一个指标，建立固定参考期；每次建立保留独立版本，不滚动吸收后续变化。
4. 选参考期之后的一次新报告，记录其实际条件，再“比较所选单次”。记录不足、条件变化、质量不足或时间重叠有具体反馈，不补出数值。
5. 选择本人感受，需要分享时先在共享设置授权“本人选择分享的情况”，再勾选同意分享本条感受。变化卡与该条自报一同按授权共享。

沿用 `recorded-conditions-3` 的严格逐项比较：人员、来源、模式、动作、侧别、目标、时间安排、数值起点、设备 / 机位、模型 / 规则、单双摄与有效性版本等。另加人工协议、椅子和支撑条件。缺失不等于相同；旧报告不补写假条件。当前严格数值起点匹配可能使跨次采样不能直接比较，后续只能在重复性研究支持下设计版本化容差，不能为显示曲线放宽门槛。

参考取中位数；工程可见覆盖门槛 0.6，至少一次完成、有有效时长且指标存在。0.6 和 3～5 次都是工程选择，不是临床界值。参考原报告与人工条件有指纹，发生改动则要求重新核对。只说明本次与参考的差异；不生成总分、诊断或自动加量建议。

### 4. 本机家庭回应和整改

“共享与提示设置”填写家属称呼并选择授权类别；默认全部关闭，可撤销。切换“本机家属”后只看所授权类别，不提供视频、骨架、设备路径或完整个人档案。

在“家庭回应与安全”选择事项，依次“我已查看”→“我来联系 / 处理”→“记录处理结果”。本人主动求助、人工整改、视觉事件和回放来源区分。整改的处理结果只提交为“待本人确认”，需本人回到页面确认才结束。实际处理说明必须人工填写，任何按钮都不代表自动到场。

原事件记录窗口为兼容旧流程仍支持“已查看 → 人工处理”；新的银发入口要求先认领。历史没有参与者归属证据的事件不猜测归属，仍可在原事件记录窗口查阅。

### 5. 可选手机演示

在共享页打开“手机家属联动（仅隔离测试资料）”。勾选测试确认后才可开启。默认地址 `127.0.0.1` **只能本机访问**；如以后现场测试手机，需显式填写电脑当前可信局域网 IPv4，手机在同一网络并打开所显示地址。程序不自动改防火墙、系统权限或路由器配置。

网页输入电脑显示的 120 秒一次性码；仍要在电脑点“我已核对手机：确认待配对家属”。点“注入 TEST_EVENT 演示求助”，网页前台每 3 秒刷新；分别查看、认领和记录处理结果，电脑列表展示真实落库回执。关闭控制窗口会撤销配对并关闭服务。

这是隔离演示，不是把本人的真实请求送到了手机。HTTPS、账户认证、真实资料授权部署、后台推送、异地通信、多人家庭与服务长期运行均未交付。没有用 HTTP 局域网宣称已完整保护敏感数据；标准库服务器也不用于生产。

## 模块、持久化与失效保护

- `activity.py` 复用既有二维姿态与时间戳状态机；任务状态变化及人工选择检查点写入原会话。未完成事件不因隐私暂停 / 断流 / 换场景自动解决。
- `change_cards.py` 为固定参考中位数及门禁；`silver_service.py` 做原会话 / 事件适配与范围过滤；`silver_store.py` 在独立 `data/silver_support.sqlite3` 保存条件附注、参考期、自报、共享策略、请求和审计。
- 原康复库结构仍为 SQLite v4，没有新迁移，不覆盖用户已有数据。新增支持库 schema v1；拒绝未知版本和未知表，逐操作自有连接、短事务、预期版本冲突检查，提交后才返回成功。
- Runtime 用独立有界可选队列处理银发 / 手机操作；采集线程只复制结构化观察快照，不跨线程使用活控制器或摄像头。原临床库仍走自身写入线程。可选数据库变慢、异常不会直接在采集调度循环等待，也不替换康复指导。显示观察快照时间，旧采集 generation 的实时状态作废。
- 家属 HTTP 仅固定隔离库，严格私网 / 回环地址、Host / Origin、JSON 大小限制、一次性码限次、HttpOnly / SameSite Cookie、会话时限与 POST CSRF 校验；无视频、无永久令牌 URL，状态更新成功响应在提交之后。网络错误明确“当前未知”，最后收到时间保留。
- 本机语音依赖已安装的 Qt 系统语音引擎，默认不开，须手动测试；没有下载或调用在线语音。未做真实音频可听度验收。

## 算法与技术资料

本轮核查的是官方接口和设计边界，不是使用者疗效或新精度证据：

- 保留当前锁定的 YOLO11 / COCO17 和已有跟踪链路，各路状态独立，不做跨镜身份拼接；官方跟踪资料见 [Ultralytics Track](https://docs.ultralytics.com/modes/track/)。没有升级模型或另训网络。
- 功能与照护需求导向参考 [WHO ICOPE 第二版](https://www.who.int/publications/i/item/9789240103726)；它不验证本项目阈值、参考次数或二维测量精度。
- 人工环境核查方向参考 [CDC STEADI 患者与家属资源](https://www.cdc.gov/steadi/patient-resources/index.html)，不是自动完成标准量表。
- 大按钮、清晰状态与文字反馈参考 [W3C 老年用户可访问性](https://www.w3.org/WAI/older-users/)；本机语音使用 [Qt QTextToSpeech](https://doc.qt.io/qtforpython-6/PySide6/QtTextToSpeech/QTextToSpeech.html)。
- 事务 / 连接管理参考 [Python sqlite3](https://docs.python.org/3/library/sqlite3.html)；隔离演示使用 [Python http.server](https://docs.python.org/3/library/http.server.html)，官方明确不推荐生产使用。Cookie 属性参见 [MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)。
