# 应用 v0.2：评估、身体信息与训练扩展

日期：2026-09-08。依据用户本次明确要求扩展：拆分评估和训练，评估后汇总用户身体信息，再进行实时训练指导，并优先增加现有模型可支持的大关节动作。本文为原 v2.1 的范围增补，不改变单路输入、隐私、保存和非诊断边界。

## 本次范围

- 业务仍为 rehab、activity、bedroom_demo、safety_demo 四场景；rehab 的两个模式在侧栏分开，身体信息是历史记录汇总页，不开启额外视频流。
- 保留肩外展与坐站，新增肩前屈、肘屈伸、坐位膝屈伸、髋外展，共六项动作、十二个动作/侧别条目。
- 身体信息来自已保存的同用户、同来源类型、同使用情境的评估，不混入训练、回放或其他人的数据。每项展示最新已结束尝试，证据不足不回退旧成功，不跨机位求均值或诊断性总分。
- 支持活动角范围、有效观察、动作完成与问题证据；不是疾病档案、临床量表、肌力或负重测量。未完成项明确显示。
- 训练必须选择当前对应的可用评估，并人工确认计划；目标默认 null，不复制评估最大值。开始时重新读取数据库校验，固化评估引用和计划。
- 所有新关节动作使用通用往返状态机，膝伸展按膝屈曲角减小处理。坐站保留达到站位计次、回坐才允许下次的原语义。
- 既有 SQLite 会话 JSON 存新增字段，汇总按需计算；无需重建表、不修改用户旧报告。身体信息可单独导出 HTML/JSON。

## 实现位置与契约

`app/exercises.py` 统一动作名称、关节、机位、主指标、必要指标、目标方向和文字提示。未知动作拒绝处理，不默认为坐站。

`app/quality.py` 测逐项二维指标；髋外展使用双髋的骨盆参考与测试腿，不以肩髋躯干角代替。`app/rehab.py` 按有效连续样本记录稳健幅度，遮挡不补零、不跨断段制造峰值。

`app/assessment.py` 从已有会话构建 `build_body_profile` 与 `build_training_reference`。`app/scene_controller.py` 在训练开始前校验用户/动作/侧别/来源/情境/最新评估，保存不可变引用。`app/runtime.py` 处理后台汇总与导出；`app/ui/main_window.py` 仅管理界面和操作。

## 验收边界

自动测试覆盖几何、状态机、报告和身份隔离、保存恢复、界面流程。Qt 离屏图像用于布局检查，合成记录始终标记 SYNTHETIC/TEST，不代表真人效果。新增四项动作的真人误差、计数准确率、受限活动度适用性、家庭机位和临床有效性仍须独立验证。

继续使用现有 YOLO11n-pose 与锁定依赖，不新增模型下载、医疗建议模型、训练平台、三维、云端或新硬件。
