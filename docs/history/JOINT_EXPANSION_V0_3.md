# v0.3 关节评估、身体信息与训练

2026-09-08。按用户要求扩展腕、踝、手指，并安装必要的本地组件及官方模型。保留原六项动作定义和历史数据，不把旧记录静默转换成新测量。

## 使用路径

1. 关闭旧版窗口后，从原来的“启动康复助手.cmd”重新打开。在身体评估选择当前用户、部位、动作和本人左/右侧。
2. 按动作说明调整机位，预览。所有正式测量都要人工确认测试侧、运动平面和关节清楚可见；软件不能精确自动判断拍摄平面。
3. 新项目在预览中记录“舒适起始姿势”。肩后伸、髋屈/后伸/内收、腕和踝还需按所选方向做舒适小幅试动作，稳定后点击“记录活动方向”，然后回起点。试动作不是最大活动度测试，也不会成为训练目标。
4. 勾选确认、确认机位、开始评估。在舒适范围活动，结束后点击“完成评估并汇总”。没有足够证据时显示缺测，不填零；即使往返不足以计次，连续有效角度仍可作为观察记录。
5. 身体信息按用户、动作、左右侧、来源及使用情境展示最新已结束记录。选择有效评估进入训练，人工确认计划后重新预览、记录本次基线并确认机位。当前角度、出程/回位、完整次数和人工目标提示实时显示；不会自动开处方或进阶。

无需做完全部 66 个左右侧项目。只选择已确认适用的动作；不适或无法清楚拍摄时停止，不为获得计数而扩大活动幅度。

## 当前覆盖

共有 33 个动作/关节任务，每项分别记录左右侧；其中 14 项为具体手指关节，不以整手总分替代。

| 部位 | 当前任务 | 必要测量点 / 限制 |
|---|---|---|
| 肩 | 外展、前屈、后伸、内收回位 | 髋、肩、肘；上臂相对躯干的二维投影，不能分离肩胛或盂肱运动 |
| 肘 | 肘屈伸、从屈肘起点伸展 | 肩、肘、腕；屈曲投影角，不测超伸 |
| 髋 | 外展、内收、屈曲、后伸 | 外/内收参考双髋与膝；屈/后伸参考肩—髋躯干线与大腿线，骨盆/躯干转动会影响结果 |
| 膝 | 坐位膝屈伸、膝屈曲、居家坐站 | 髋、膝、踝；坐站另需舒适坐位/站位基线，不套标准坐站常模 |
| 腕 | 屈曲、伸展、桡偏、尺偏 | 同一帧的 Pose33 肘/腕与 Hand21 腕/中指掌指点；区分侧缘拍摄和掌/背面拍摄，须匹配指定侧手部 |
| 踝 | 背屈、跖屈 | 膝—踝小腿向量与足跟—足尖向量；稳定坐位侧面，不以踮脚、抬腿或膝角代替踝角 |
| 手指 | 拇指 MCP/IP；食指、中指、无名指、小指各 MCP/PIP/DIP | 单只手近景、所测手指侧面清晰；非拇指 MCP 以腕—掌指连线为近端代理，不是骨性关节测量 |

腕、踝和手指标为“实验性二维观察”，尚无真人对照准确度证据。Hand21 不提供逐关节点置信度，保存为 null，绝不拿左右手分类分数冒充。橙色点表示置信度未知。短时连续性、点间长度、画面边界和匹配检查只能发现部分失败，不能保证自动识别所有遮挡、指间重叠或离面运动；模型也可能在遮挡处估点，需要人工观察与停止。

肩后伸、髋屈/后伸/内收、腕和踝报告的是相对本次舒适起点、按人工指定方向的有符号投影变化，不是绝对临床 ROM。向相反方向移动可以出现负值，但不会算作目标方向的完整动作。

暂不输出：肩/髋轴向旋转、肩水平内外收、前臂旋前旋后、踝内外翻/足弓、拇指腕掌/对掌、手指侧向外展、各颈胸腰椎节段角。原因也列在身体信息中：关键点或观测平面不足，不能把外观位移当成这些关节的可靠测量。肌力、疼痛和疾病不从骨架推断。

## 本地组件和复现

- 原来的 `.venv` / YOLO11n-pose 不变。仅新动作需要 `.venv-landmarks`，MediaPipe 固定为 1.0.1，完整版本在 `requirements.landmarks.lock.txt`。
- Google 官方固定版本的 `pose_landmarker_full.task`、`hand_landmarker.task` 已在本机准备。URL、SHA256 和尺寸见 `assets/models/landmarks-manifest.json`。权重和独立环境不进 Git。
- 原动作选择 YOLO；踝选择 Pose33；手指选择 Hand21；腕在同一个模型进程中对同一帧使用 Pose33+Hand21，显式组合为 `mediapipe-wrist54-v1`。没有第二路采集，所有模型进程都不打开摄像头、不访问用户数据库。
- 主程序不导入 MediaPipe、不在启动时下载。缺组件、哈希不符或超时只阻止需要该组件的动作；重新预览后才重试，原动作可以继续用。
- 模型进程使用 IMAGE 模式，不带跨用户/回放跳转的隐式跟踪；空间连续性编号只在本次上下文内辅助归属，不是人的身份。切换、隐私暂停和旧包拒收沿用原单路机制。

另一台 Windows 电脑在主项目环境准备好后，明确运行：

```powershell
.\scripts\setup_landmarks.ps1
```

仅检查，不联网安装或下载：

```powershell
.\scripts\setup_landmarks.ps1 -VerifyOnly
```

脚本不覆盖已有哈希不符的模型。代码、模型、训练数据的许可应分别核查，见 `../dependencies/THIRD_PARTY_NOTICES.md`；本地实验不代表取得商用/医疗用途授权。

## 数据与版本

应用规则 `rules-0.3.0`、预处理 `causal-ema-schema-0.3.0`。会话保存实际骨架 schema、关节顺序、模型哈希、处理后端、测量定义、基线来源和方向确认。原 SQLite 表结构不变。

基线绑定本次预览、参与者编号、临时跟踪编号、侧别、动作、机位、实际画面尺寸、来源、模型和 schema；不接受界面伪造的角度。重新预览、变更条件后须重录。基线参与配置版本标识，不同起点的相对测量不会被当成同条件变化。

普通报告不需要骨架保存授权。导出继续匿名化参与者和来源，包括嵌套的基线及训练引用。未授权时不导出逐帧骨架或视频。

## 验证边界

自动验证包含已知几何、逐手指关节、零长/缺点/低置信度、角度跨 ±180°、起点连续性、方向必填、每项完整往返、保存重开、训练引用、旧基线/伪造基线拒收、界面分组和空白图像实际模型加载。详细实际结果记录在 `../validation/HISTORY_WINDOWS.md`。

合成几何正确、空白图推理成功和界面可启动，不等于真人测量准确或患者可安全使用。仍需在允许的动作范围内，对每个新增项目做真人可见性检查及独立人工二维参考对照；尚未完成 USB 拔插、30 分钟真人连续使用或临床验证。不隐藏这个边界，也不以本次测试数量宣称医疗有效性。
