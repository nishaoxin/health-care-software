# 0.11.0：逐动作时间与人工安排

本阶段为现有动作增加独立的时间证据。原有完成次数、角度目标、观察质量和可见问题仍分别保留；不会因未达到时间安排而扣掉完整次数。

## 如何定义

| 指标 | 普通关节往返 | 居家坐站 |
| --- | --- | --- |
| 出程 | 触发本次出程前一条有效观测，到峰区起点 | 同样的观测起点，到既有规则确认站位的时刻 |
| 峰区 / 站位停留 | 峰区首尾观测之间的时间 | 站位确认到首次持续离开站位进入回坐的边界 |
| 回程 | 峰区终点到既有规则确认返回起点的时刻 | 回坐边界到既有规则确认坐回的时刻 |
| 最长连续保持 | 人工角度目标范围内最长的一段相邻有效观测时间；未设目标留空 | 同时满足本次校准膝角、髋高站位范围的最长连续观测时间 |

关节峰区在完整往返结束后计算：按目标方向统一正负，连续三点中位数放在中心样本的源时间，距本次最大值 3° 内的一段区域为峰区。多段峰区、阶段边界不足、样本不足或过程中缺测时，相应分期无法确定；不把 `PEAK_OR_HOLD` 的计数状态当成已达到保持。它是事后观察统计，不用于实时读取未来帧，也不代表生理阶段或稳定站立能力。

时间分辨率受实际采样、滤波、画面质量和已有阶段确认停留影响，未做真人计时误差验证。新出程起点与旧总时长起点定义不同；旧 `duration_s` 保留原用途，不要求新三个阶段之和等于旧总时长。坐站起立在确认站位时仍计一次，回坐另行观察；停止在站位不会补造回程。

保持使用已经到达的有效源时间。离开目标、遮挡、换人、断流、暂停会断开连续段，分段不相加。已明确观察到的一段达到保持目标，可独立记达到；若有缺测且最长可见段仍不足，不判未达到而记无法评价。各指标保存 `value / valid / reason`；缺测为 null，0 秒只用于有观察但没有正持续间隔的结果。

## 计划、界面与旧记录

在本次计划或个人计划库中，可人工填写出程 / 回程最短最长及连续保持至少几秒，范围 0–300 秒，默认全为空。普通关节的正保持目标需要明确人工角度锚点；坐站使用每次重新确认的站位范围。不会从评估结果推荐时长或自动进阶。

普通界面和大字指导显示本段保持。坐站到达本组次数后，未完成的人工保持优先于回坐图解；质量提示、缺测、暂停和断流仍优先。保持结果不自动开关相机，也不自动进入下一组。

新会话 / 重复记录带 `observed-timing-1`。数据存于现有 SQLite JSON，不升级数据库结构、不重写个人历史。旧计划没有 `timing_plan` 时按未设置兼容；已有坐站下降时间可读入回程安排，编辑保存后采用新字段。旧报告缺少时间证据时明确显示未记录，不从总时长补算。

报告另列时间表；JSON 保留完整定义、有效性、原因和各目标状态，CSV 逐列导出同一数值、有效性、原因、目标状态及安排。普通导出的既有去标识化规则继续适用。

## 验证

本阶段固定回归覆盖 **1187 项主测试与 4 项子测试，0 失败 / 错误 / 跳过**：核心 618、原生界面 354、集成 215，49 个文件。核心与集成来自完整 9 批运行；大字保持优先级改动后的界面批次单独重新运行，统计不重复相加。另对最后的文字状态调整运行相关 UI 测试。[逐批证据](../validation/results/2026-09-10-timing-v011.json)保留来源和原始摘要。

新增固定轨迹检查包含正反方向、已知出程 / 峰区 / 回程时间、分段保持、短遮挡、长间隔、乱序帧、换人、暂停、坐站达站后继续保持、回程缺测、旧计划兼容，以及 SQLite 重开后 HTML / JSON / CSV 一致性。旧计数、其他场景、真实 YOLO / MediaPipe SDK 和合成回放回归通过。

`scripts/qa_movement_timing.py` 使用合成观测和临时 SQLite，经原生控件确认计划、显示站位保持与大字进度、保存重开并导出。已目视检查计划窗口、普通训练页、大字保持页和报告时间表；截图测试最初未注册中文字库，已在 QA 脚本中显式加载本机字体后重做检查。
