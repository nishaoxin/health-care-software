# 双版本融合 · 0.15.0 · 2026-09-12

## 来源与取舍

用户要求融合两版各自改动的优势。以 GitHub `main` 的 `f7c69bb2dfc4bc6b346561f1fb298144975c0789` 为当前基底，合入本地保留分支 `backup/local-199a265` 的 `199a265cfa2ff672d649632a919e10965d3f959c`；共同祖先为 `acd2dd0`。使用双父 merge 保留两边历史，不用文件覆盖或硬重置替代融合。提交前再次 fetch，远端 main 仍是上述 GitHub 提交。

| 来源 | 保留的优势 | 融合衔接 |
| --- | --- | --- |
| 本地逐步版本 | 每步操作提示、头颈髋点解释、保存后结果解读、训练反馈后打开报告 | 记录步骤改接倒计时；最终按钮承载人工确认，不再要求重复勾选 |
| GitHub 提示版本 | 短暂缺测缓冲、普通 / 大字共享提示、稳定新帧采样、取消与重试 | 步骤页沿用同一提示来源；记录状态移至固定下方操作区，避免藏在设置页 |
| GitHub 双摄版本 | 主测量与辅助几何独立有效性、人员归属门禁、原始证据与比较版本 | 通俗结果页解释新规则，详细报告及 HTML / JSON / CSV 保留原记录；旧报告不按新规则重算 |

## 统一流程与修复

选择动作 → 打开预览 → 调整机位 → 按动作记录起点 / 方向或坐站位 → 回到起点，点击“已核对，确认准备” → 另行开始 → 完成并保存 → 结果解读 / 详细数据。训练还需先选择评估依据、确认本次计划，结束后可填写或跳过感受。

- 起点、方向、坐站统一请求 `prepare_sample`，保留 3 秒倒计时与原稳定新帧要求。采样期间不因基线消息先到而提前推进；主按钮禁用，也不能重复调用。取消、停止采集不被忙碌状态遮挡。
- 融合时发现本地 `_render_journey` 会覆盖远端的按钮禁用状态，已修复；原坐站步骤直接单次请求基线，已接入同一连续采样流程。
- 原本地“必须先勾选”的前置分支与远端“一次按钮确认”冲突，已移除重复确认。陪同要求仍显式勾选，后台身份、基线、测量质量、计划和保存门禁没有放宽。
- 采样状态、取消与重试共用一组固定控件；倒计时用 20px 文字，进行中步骤明确要求等待。变更动作 / 来源等上下文时清除旧请求和旧提示。
- 步骤页与其他指导页使用同一运行时提示；普通无效帧仍即时排除，持续 1.5 秒缺测才给调整指令。硬故障不缓冲，没有通过隐藏提示假装测量成功。
- 结果页先显示康复指标与通俗解释，详细证据保留；双摄新版解释辅助指标缺测与主结果的区别，旧版提示沿用原规则。说明头颈的髋点用于躯干参考，不是评估髋关节，不需要裸露皮肤。
